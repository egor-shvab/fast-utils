# CLAUDE.md — заметки для ИИ-агентов

FastUtils — фоновое приложение для macOS, которое живёт только в строке меню. Шесть функций по глобальным сочетаниям клавиш: распознавание текста в области экрана (⇧⌘1), скриншот с рисованием (⇧⌘2), перевод буфера обмена или выделенного текста (⌥⌘T), история буфера обмена с быстрой вставкой (⌥⌘V), «Раскладка и регистр» (⌥⌘R — исправить раскладку, ⌥⌘U — сменить регистр) и пипетка цвета (⌥⌘P). Приложение пишется только для личного использования владельцем проекта.

Приложение готово и используется. Дальнейшая работа — исправления и доработки по просьбе пользователя. Для человека — [README.md](README.md), для агента — этот файл.

## Что нельзя сломать

Ключевые требования, о которых договорились с пользователем. Менять — только после его согласия.

- **Не мешать.** Нет иконки в Dock и окон при запуске (`LSUIElement`). Всплывающие окна не забирают фокус дольше нужного и закрываются по Esc или клику мимо. Панели появляются на экране с курсором, поверх полноэкранных приложений и на текущем Space.
- **Ресурсы и скорость.** CPU в простое ≈ 0 %, память < 80 МБ без открытых окон. Окно истории открывается < 150 мс, оверлей распознавания < 200 мс, текст в буфере ≤ 1 с после выделения, перевод Apple короткого текста < 1 с. Время OCR и окна истории пишется в лог — сравнивай с этими цифрами.
- **Приватность.** Пароли (concealed-типы) и приложения-исключения не попадают в историю, а их содержимое даже не читается. Содержимое буфера, распознанный и переводимый текст, ключи API не пишутся в логи. Ключи — только в Keychain. История хранится локально, без шифрования (её защищает FileVault).
- **Перевод.** По умолчанию на русский, а если текст уже русский — на английский (оба языка настраиваются). Apple Translation работает без интернета; DeepL и Google — по ключу пользователя с откатом на Apple при ошибке.
- **Сочетания клавиш** работают в любой раскладке (в том числе русской), каждое переназначается и снимается, каждая функция выключается. Выключенная функция не реагирует, не держит сочетание и не показывается в меню.
- **Настройки.** Окно с боковой панелью: Основные / страница каждой функции / О программе. Всё, что относится к функции, — только на её странице. Изменения применяются сразу, без кнопки «Сохранить». Интерфейс на русском и английском.
- **Платформа.** macOS 15+, только Apple Silicon, без App Sandbox: глобальные сочетания, имитация ⌘V и снимок экрана с ним не работают.

## Правила работы

- **Язык:** с пользователем и в документах (README.md, CLAUDE.md) — по-русски. Код, идентификаторы, комментарии в коде и сообщения коммитов — по-английски. Строки интерфейса — только через `Localizable.strings` (ru и en, ключи в обоих файлах совпадают), основная локаль — русский.
- **Требования не меняем молча.** Если просьба противоречит разделу «Что нельзя сломать» или есть вариант лучше, спроси пользователя.
- **Предпочтение пользователя: простые и прямолинейные решения.** Пример: для отслеживания буфера пользователь отклонил «умный» гибрид (события ⌘C, мышь, адаптивный таймер) как костыль и выбрал простой таймер на 0,5 с. Не усложняй без явной пользы, а если усложнение кажется нужным, сначала предложи его.
- **После изменения:** `swift build`, тесты, `scripts/build.sh --install`, затем попроси пользователя проверить вручную — агент не видит экран и не может нажимать сочетания.
- **Коммиты и пуш — только по просьбе пользователя.**
- **Подводные камни записывай сюда**, в раздел ниже, сразу как столкнулся: что случилось, почему, как обойти.

## Окружение

- Mac на Apple Silicon, macOS 27. **Xcode не установлен, и это осознанно:** пользователь не хочет засорять систему. Есть только Command Line Tools (`/Library/Developer/CommandLineTools`): Swift 6.4, SDK macOS 27. Homebrew не установлен. Не предлагай ставить Xcode или Homebrew без серьёзной причины.
- Сборка — Swift Package Manager + `scripts/build.sh`, который собирает `.app`-бандл и подписывает его. В CLT **нет** `actool`, `xcstringstool`, `ibtool`, поэтому:
  - нет Asset Catalog: иконка приложения собирается в `.icns` через `iconutil`, иконка меню — SF Symbol или PDF;
  - нет String Catalog (`.xcstrings`): используется `.lproj/Localizable.strings`;
  - нет `.xib`/`.storyboard`: весь UI в коде (SwiftUI + AppKit);
  - нет SwiftUI Previews: проверяем запуском приложения;
  - **нет плагинов SwiftUI- и SwiftData-макросов** — см. «Подводные камни» → «SwiftUI без Xcode». Работают только `@Observable` (Observation) и макросы стандартной библиотеки.
- Цель сборки: **только arm64**, deployment target **macOS 15**. API новее 15 используются через `if #available`.
- Bundle id: `com.yahor.FastUtils` (зафиксирован в `Resources/Info.plist`, `AppInfo.bundleIdentifier` и `scripts/build.sh`; после выдачи разрешений не менять, иначе macOS попросит их заново).
- Подпись: самоподписанный сертификат `FastUtils Dev` в login keychain, создаётся `scripts/create-signing-cert.sh` (OpenSSL → p12 → `security import -T /usr/bin/codesign`). Сертификат не помечается доверенным в системе — для `codesign` это не нужно. Если сертификата нет, `build.sh` подписывает ad-hoc и предупреждает.
- В репозитории есть `.idea/` (IDE пользователя) — он в `.gitignore`, не трогай его.

## Команды

```bash
swift build                          # быстрая проверка компиляции
perl -e 'alarm 300; exec @ARGV' swift test   # юнит-тесты (Swift Testing) с защитой от зависания
scripts/build.sh                     # release-сборка в build/FastUtils.app
scripts/build.sh --debug             # debug-сборка с get-task-allow (можно подключить lldb)
scripts/build.sh --run               # собрать, перезапустить из build/ и стримить логи приложения
scripts/build.sh --install           # собрать, установить в /Applications и перезапустить
scripts/release.sh                   # DMG установщика в build/FastUtils-<версия>.dmg (версия из Info.plist)
scripts/create-signing-cert.sh       # один раз на Mac: создать сертификат "FastUtils Dev"
swift scripts/make-icon.swift        # перегенерировать Resources/AppIcon.icns
/usr/bin/log show --last 5m --style compact --predicate 'subsystem == "com.yahor.FastUtils"'
footprint FastUtils                  # реальная память процесса (phys_footprint), RSS завышен общими библиотеками
leaks FastUtils                      # утечки; нужна debug-сборка (get-task-allow)
```

Структура: `Sources/` (код), `Tests/` (тесты), `Resources/` (Info.plist, entitlements, иконка, `*.lproj`), `scripts/` (сборка), `build/` (собранный `.app`, в git не попадает).

## Архитектура

- **Ядро (`Sources/Core`) + модули-функции (`Sources/Feature*`).** Модуль реализует протокол `Feature`, регистрируется одной строкой в `Sources/FastUtilsApp/FeatureList.swift`.
- Устройство ядра: `Core/Feature/` — `Feature`, `FeatureAction` (структура: id + название + `@MainActor`-замыкание), `FeatureRegistry` (включение/выключение, хранит флаг в `features.<id>.enabled`); `Core/Services/` — `SettingsStore`, `AppPreferences` (язык интерфейса, видимость иконки), `SecretStore` (Keychain / in-memory), `StorageService`, `EventBus`, `ActionRegistry`, `PermissionsService`, `LaunchAtLogin`; `Core/UI/` — `MenuBarController`, `SettingsWindowController` + `SettingsView`, скрытое главное меню `MainMenu`, онбординг, `HUDService`, `PanelService`. Остальные части ядра — `Core/Hotkeys`, `Core/Pasteboard`, `Core/Screen`, `Core/Storage` (см. «Подводные камни» ниже).
- Всё ядро — `@MainActor`. Действия выключенного модуля в `ActionRegistry` отсутствуют, вызов даёт `ActionError.notFound`.
- В тестах используй `AppContext.testing()` — отдельный UserDefaults-suite, секреты в памяти, временный каталог.
- **Модули зависят только от `Core`, но не друг от друга.** Связки (например, «распознать и перевести») делаются через `ActionRegistry` по `ActionID`. Межмодульный импорт запрещён и должен ломать сборку на уровне `Package.swift`.
- **Сервисы — через `AppContext`** (внедрение зависимостей). Синглтоны и глобальное состояние не используем, `shared`-объекты не заводим.
- **С `NSPasteboard` напрямую не работаем**, только через `PasteboardService` из Core. Иначе история начнёт путать «технические» записи приложения (перевод выделенного, вставка из истории) с копированием пользователя.
- **Панели — только через `PanelService`**, HUD — через `HUDService`, чтобы поведение было единым: позиция у курсора, Esc, клик мимо, Spaces, полноэкранные приложения.
- **Настройки функции — только на её странице.** Окно настроек — `NavigationSplitView`: слева список (Основные / Функции / О программе), справа страница. Новая функция задаёт `title`, `icon`, `summary` (строка в шапке) и `tint` (цвет плашки) — по ним строятся пункт списка и шапка (`Core/UI/SettingsComponents`). Страницу собирает ядро (`Core/UI/FeatureSettingsView`): шапка с «Включено», сочетания действий, разрешения из `requiredPermissions`, затем `Feature.settingsView`. `settingsView` отдаёт **только `Section`-ы в `Group`**, без своего `Form`/`.formStyle` (иначе форма окажется внутри формы). Пока функция выключена, всё ниже переключателя `.disabled`. Отдельных страниц «Сочетания»/«Разрешения» нет, в «Основных» — только общее для приложения.
- Настройки модуля — в его пространстве имён (`ocr.*`, `translate.*`, `clipboard.*`, `text.*`, `color.*`, `screenshot.*`), секреты — только в Keychain.
- Swift 6 strict concurrency: всё, что касается UI и AppKit, помечается `@MainActor`. Тяжёлая работа (Vision, генерация превью, сеть, БД) выполняется вне главного потока.
- Логи: `os.Logger` с категорией модуля. **Содержимое буфера, распознанный и переводимый текст, ключи API в логи не пишем никогда.**

## Известные подводные камни

Известные заранее:

- **Подпись и разрешения (TCC).** macOS привязывает выданные разрешения («Запись экрана», «Универсальный доступ») к подписи приложения. При ad-hoc подписи (`codesign -s -`) подпись меняется с каждой сборкой, и разрешения сбрасываются. Поэтому подписываем постоянным самоподписанным сертификатом `FastUtils Dev`. Если разрешения «залипли» в странном состоянии: `tccutil reset ScreenCapture com.yahor.FastUtils` (аналогично `Accessibility`), затем выдать заново.
- **Нет события изменения буфера.** Публичного уведомления в macOS нет, поэтому опрашиваем `changeCount` раз в 0,5 с. Это решение пользователя, не меняй его без согласования (см. «Правила работы»).
- **Приватность буфера в macOS 26+.** У пользователя есть настройка доступа приложений к буферу («Вставка из других приложений»). Первое программное чтение показывает системный запрос; подробности — в разделе «Буфер обмена, история, вставка» ниже (`accessBehavior`).
- **Пароли в буфере.** Менеджеры паролей помечают записи типами `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`. Список и правило — в Core (`PasteboardPrivacy`): такие записи не попадают в историю, и ни один модуль не получает их текст (`readText()`/`readImage()` возвращают `nil`, проверка — `containsConcealed`). Раньше фильтр был замыканием модуля истории, и перевод (⌥⌘T) отправлял пароль из буфера в DeepL/Google, а с «копировать перевод» — и в историю. **Правило: всё, что читает буфер для функции, идёт через `readText()`/`readImage()`, никаких обходов.**
- **Снимок экрана.** `CGWindowListCreateImage` устарел начиная с macOS 15, используем `ScreenCaptureKit` (`SCScreenshotManager`). Учитывай `backingScaleFactor` и разные масштабы мониторов.
- **Apple Translation на macOS 15.** `TranslationSession` нельзя создать напрямую, она доступна только через SwiftUI-модификатор `.translationTask`, поэтому нужен SwiftUI-хост. Прямой инициализатор появился в macOS 26 — использовать через `if #available`.
- **Сочетания клавиш и раскладка.** Регистрируем по key code (Carbon, свой модуль `Core/Hotkeys`), а не по символу, иначе в русской раскладке ничего не сработает. Имитация вставки — `CGEvent` с `kVK_ANSI_V` + `.maskCommand`.
- **Secure Input.** Когда активно поле ввода пароля, имитация нажатий может не работать. Это ожидаемо: запись остаётся в буфере.
- **Конфликты сочетаний.** ⌥⌘V в Finder означает «переместить объект сюда», ⌥⌘T в некоторых приложениях занят. Пользователь знает об этом и может переназначить.
- **Агент без Dock.** `LSUIElement = YES`: у приложения нет главного меню, поэтому стандартные ⌘C/⌘V/⌘A в текстовых полях окон настроек не работают без меню «Правка». Решено: `MainMenu.install()` ставит скрытое главное меню с «Правкой» — эквиваленты клавиш проходят через `NSApp.mainMenu`, даже когда строка меню не показывается.
- **Панели и фокус.** Для окна истории нужна панель, которая принимает ввод с клавиатуры (поиск), но потом возвращает фокус предыдущему приложению перед вставкой. Запоминать `NSWorkspace.shared.frontmostApplication` **до** показа панели.

Найденные в ходе разработки — по темам. Дописывай сюда сразу, как столкнулся: что случилось, почему, как обойти.

### Сборка и окружение

- **Предупреждения линкера.** `ld: warning: search path '/Library/Developer/CommandLineTools/Developer/...' not found` появляется при каждой сборке: в CLT нет каталога Developer-фреймворков. Это безвредно, `build.sh` их фильтрует. Код возврата `swift build` берётся из `PIPESTATUS[0]`: раньше `| grep … || true` гасил ошибку компиляции, и скрипт собирал и устанавливал **прошлый** бинарник с «✔».
- **Сертификат подписи.** `FastUtils Dev` создан, SHA-1 `38739094F765AA7730F3D1C43A0DF7AFC3433A1F`. `security find-identity` показывает его с `CSSMERR_TP_NOT_TRUSTED` — это нормально, подпись работает без запросов пароля. Поэтому ищем его **без** флага `-v` (с `-v` видны только доверенные). Требование подписи: `identifier "com.yahor.FastUtils" and certificate leaf = H"38739094…"` — одинаковое у всех сборок, проверка: `codesign -dr - build/FastUtils.app`. Если сертификат пересоздать, хэш изменится и все разрешения придётся выдавать заново.
- **После удаления зависимости** SwiftPM пытается клонировать её снова («dependency … is missing; cloning again»): удали `.build/workspace-state.json` (и `Package.resolved`, если зависимостей не осталось).
- **Ресурсы SwiftPM-зависимостей.** `build.sh` копирует `*.bundle` из каталога сборки в `Contents/Resources`. Сгенерированный SwiftPM аксессор `Bundle.module` может искать бандл в корне `.app` (а туда класть файлы нельзя — сломается подпись). Пока не проверено: сторонних зависимостей с ресурсами нет (от `KeyboardShortcuts` отказались — она требует SwiftUI-макросов). Проверить, если такая зависимость появится.
- **Падение компилятора.** Key path к статическому свойству через экзистенциальный метатип (`types.map(\.id)`, где `types: [any Feature.Type]`) роняет Swift 6.4 в SILGen («Stack dump… While silgen constructor»). Пиши замыкание: `types.map { $0.id }`. Если компилятор падает без понятной ошибки — ищи такие конструкции.
- **`switch`-выражение** нельзя использовать справа от `??` («'switch' may only be used as expression in return, throw, or as the source of an assignment») — сначала присвой его в отдельную константу.
- **Релиз.** Версия — `CFBundleShortVersionString`/`CFBundleVersion` в `Resources/Info.plist`; меняй их `sed`-ом, а не `plutil -replace`: тот пересортировывает все ключи и раздувает дифф. `scripts/release.sh` собирает DMG через `hdiutil` (UDZO, HFS+) и подписывает его тем же сертификатом. Тег `v<версия>`; релиз на GitHub пользователь выкладывает сам через сайт, `gh` не установлен. Push — тоже пользователь: у шелла агента нет доступа к его SSH-ключу.
- **«CUICatalog … unable to find a bundle» в логах.** Сотни сообщений уровня fault от CoreUI: у приложения нет `Assets.car` (в CLT нет `actool`). Безвредно, было с самого начала — не ищи в них причину проблем.

### SwiftUI без Xcode

- **SwiftUI/SwiftData-макросы без Xcode НЕ компилируются.** В CLT есть плагины только `ObservationMacros`, `SwiftMacros` и `testing`. Поэтому запрещены: `#Preview`, `@Entry`, **`@State`** (в SDK macOS 27 это макрос!), SwiftData `@Model`/`#Predicate`. Ошибка: «external macro implementation type 'SwiftUIMacros.…' could not be found». Работают: `@StateObject`/`@ObservedObject` + `ObservableObject`, `@Binding`, `@Bindable`, `@Environment`, `@FocusState`, `@AppStorage`, `@Namespace`, `@Observable`. **Локальное состояние SwiftUI-вью — через `@StateObject` с маленьким `ObservableObject`** (пример — `RecorderState` в `ShortcutRecorder.swift`). Сторонние библиотеки перед подключением проверять на эти макросы (`grep -rn "#Preview\|@Entry\|@State\b\|@Model"`): так отпала `KeyboardShortcuts`.

### Тесты

- **Проверки всего проекта — `Tests/AppTests`** (зависит от исполняемой цели, `@testable import FastUtilsApp` работает): каждый `ActionID` в `perform("…")`/`actionID: "…"` объявлен каким-то модулем из `featureTypes`, ключи ru/en совпадают, каждый литеральный ключ из кода есть в `.strings`/`.stringsdict`. Исходники ищутся от `#filePath`. Ключи, собранные во время выполнения (`"clipboard.filter.\(rawValue)"`), не проверяются.
- **Тесты без Xcode.** XCTest в Command Line Tools нет. Используем **Swift Testing** (`import Testing`, `@Test`, `#expect`) — он работает через `swift test`. Не пиши тесты на XCTest.
- **Плагин макросов Swift Testing.** Новая система сборки SwiftPM (Swift Build, по умолчанию в 6.4) с одними CLT **случайным образом** не передаёт тестовым целям путь к `TestingMacros` → «plugin for module 'TestingMacros' not found». `--build-system native` не помогает (не находит модуль `Testing`). Решение в `Package.swift`: `testSettings` с `-plugin-path …/host/plugins/testing` для каждой `testTarget`. **Новые тестовые цели создавай с `swiftSettings: testSettings`.**
- **Зависание тестов.** Тест, который ждёт событие из `AsyncStream`, висит вечно, если событие не пришло (например, выключение модуля, который не был запущен, ничего не публикует). Всегда запускай тесты через `perl -e 'alarm 300; exec @ARGV' swift test` (в macOS нет `timeout`).
- **Строгая конкурентность в тестах.** Замыкание в `#expect(throws:)` не должно возвращать не-`Sendable` значение (`ActionOutput`): пиши `_ = try await …`.
- **Краш-репорты тестов** лежат в `~/Library/Logs/DiagnosticReports/swiftpm-testing-helper-*.ips` (JSON после первой строки; причина — в поле `asi`, стек — в `threads[faultingThread]`). Если `swift test` пишет «Process … swiftpm-testing-helper … exited» без подробностей — смотри туда.

### Диагностика и проверка агентом

- **`log` в zsh.** В zsh `log` — встроенная команда, поэтому `log show …` падает с «too many arguments». В интерактивном шелле агента вызывай **`/usr/bin/log`**. В bash-скриптах проблемы нет.
- **Уровни логов.** Сообщения `Logger.info`/`.debug` **не сохраняются** в системный журнал и видны только в живом `log stream --level debug` (так работает `build.sh --run`). То, что нужно увидеть потом через `log show`, пиши уровнем `.notice` и выше.
- **`open` на запущенном приложении** только активирует уже запущенную копию и не перезапускает её. Перед запуском новой сборки делай `pkill -x FastUtils` (`build.sh --run/--install` делают это сами).
- **Визуальная проверка.** Агент не может сделать снимок экрана из своего шелла (`screencapture` → «could not create image from display»: у процесса агента нет разрешения на запись экрана). Чтобы проверить UI, попроси пользователя посмотреть или используй computer-use, если он доступен. Факт запуска проверяется по `pgrep -x FastUtils` и логам; признак агента без Dock — `type="UIElement"` в `lsappinfo list`.
- **Симуляция нажатий агентом запрещена.** `osascript … keystroke` → ошибка 1002 (нет права «Универсальный доступ» у процесса агента). Проверка горячих клавиш — по логу `Registered ⇧⌘1 for ocr.captureText` (категория `hotkeys`) и вручную пользователем.
- **Проверка окон без скриншотов.** Скрипт на `CGWindowListCopyWindowInfo` с фильтром по `kCGWindowOwnerName == "FastUtils"` показывает слой и размеры окон приложения — разрешения на запись экрана для этого не нужно. Так можно убедиться, что окно открылось. Повторный `open build/FastUtils.app` при запущенном приложении открывает настройки (`applicationShouldHandleReopen`).
- **Замеры и утечки.** Память смотри через `footprint` (14–24 МБ), а не RSS (~65–90 МБ). `leaks` даже в простое показывает ~416 объектов / 20 КБ — это циклы системного XPC-соединения AppIntents (`com.apple.linkd.autoShortcut`), не наш код; сравнивай с этим фоном. Время OCR и открытия окна истории пишется в лог уровнем `.notice` (`Recognized … in N мс`, `History window opened in N мс`) — собирай статистику из `log show` реального использования.

### Ядро: горячие клавиши, меню, настройки

- **Запись сочетания.** Пока строка записывает, горячие клавиши сняты (`HotkeyService.beginRecording/endRecording`). Записывает только одна строка: `beginRecording` сначала останавливает предыдущую, иначе её остановка возвращала горячие клавиши посреди записи во второй строке.
- **Свои горячие клавиши.** `Core/Hotkeys`: `Shortcut` (key code + модификаторы, имя клавиши — латинская подпись физической клавиши → в русской раскладке показывается «⌥⌘T»), `CarbonHotkeyRegistrar` (`RegisterEventHotKey`, без разрешений), `HotkeyService` (объявление всех действий, активация только включённых, хранение `hotkeys.<actionID>` = `{keyCode, modifiers}` или `"none"`), `ShortcutRules` (запрет/предупреждения, системные сочетания через `CopySymbolicHotKeys`). В тестах — `FakeHotkeyRegistrar` через `AppContext.testing(hotkeys:)`, реальные горячие клавиши в тестах не регистрируются.
- **Конфликт с другими приложениями не определить.** Два процесса могут зарегистрировать одно и то же сочетание через `RegisterEventHotKey`, оба получают `noErr` (проверено экспериментом). Не пытайся «проверить занятость» регистрацией.
- **Text Input Sources API роняет процесс** (`abort`), если вызвать его из двух потоков одновременно («TIS/TSM API is being called in two threads concurrently»). Поэтому `Shortcut.keyName` больше не спрашивает раскладку у системы, а берёт латинские подписи клавиш из статической таблицы по `kVK_ANSI_*`. Не возвращай `TISCopyCurrent…` в код, который может выполняться вне главного потока (а `description` — может).
- **Меню и иконка.** `MenuItemDescriptor` умеет действие (`actionID`, показывает сочетание), обработчик без действия (`.custom`), неактивную подпись (`.label`) и подменю (`.submenu`). Меню пересобирается при каждом открытии, так что пункты могут зависеть от состояния. Иконка в строке меню меняется через `context.statusIndicator.set(symbol:tooltip:)`.
- **Экспорт настроек.** `SettingsStore.exportJSON/importJSON` берут только ключи с префиксами FastUtils (`app.`, `features.`, `hotkeys.`, `ocr.`, `translate.`, `clipboard.`); ключи API не попадают — они в Keychain. Модули читают настройки при запуске, поэтому после импорта — перезапуск (`AppRelauncher`).
- **Язык интерфейса.** Выбор хранится в `app.language` (`system`/`ru`/`en`), а применяется в самом начале `main.swift` (`InterfaceLanguage.applyStored()`): пишет `AppleLanguages` в домен приложения или удаляет его для «как в системе». Работает только при запуске — до первой локализованной строки, поэтому после смены языка предлагаем перезапуск. `AppleLanguages` в экспорт настроек не попадает, только `app.language`. В тестах suite-домен наследует глобальный `AppleLanguages` — проверяй `persistentDomain(forName:)`, а не `object(forKey:)`.
- **Скрытая иконка.** `app.menuBarIcon` → `statusItem.isVisible` (наблюдение через `AppPreferences`). Путь назад — повторный запуск приложения: `applicationShouldHandleReopen` открывает настройки.
- **Онбординг и автозапуск.** Флаг онбординга — `app.onboarding.completed` в UserDefaults; показать окно снова: `defaults delete com.yahor.FastUtils app.onboarding.completed` и перезапуск. `SMAppService.mainApp` регистрирует приложение по текущему пути — поэтому для реального использования ставим в `/Applications` (`scripts/build.sh --install`), а не запускаем из `build/`.
- **Связки модулей.** Действие объявляет, с чем работает: `FeatureAction(accepts: [.text]/[.image], contentTitle:)`; другие модули находят такие действия через `context.actions.actions(accepting:excluding:)` и вызывают по `ActionID` — **без импорта модулей друг в друга**. Примеры: `ocr.recognizeImage` (картинка → текст), `translate.show` (текст → окно перевода), `ocr.captureAndTranslate`. Если модуль-исполнитель выключен, `perform` бросает `ActionError.notFound` — обрабатывай подсказкой.

### Локализация

- **Множественное число.** Для русских форм («1 символ / 2 символа / 5 символов») — `Localizable.stringsdict` в `ru.lproj`/`en.lproj` и `String.localizedStringWithFormat(NSLocalizedString(key, comment: ""), n)`. `build.sh` копирует его вместе с `.strings`.

### Окна, панели, HUD

- **Общие окна.** Всплывающие панели — только `context.panels.toggle/present(id:size:placement:content:)` (`FloatingPanel`: `.nonactivatingPanel`, принимает ввод, не активируя приложение; закрывается по Esc и потере фокуса, если не закреплена через `PanelHandle.isPinned`). Уведомления — `context.hud.show(_:icon:style:)`; ошибки (`.error`) показываются даже при выключенных уведомлениях. Позиционирование — `ScreenGeometry` (чистые функции, покрыты тестами).
- **HUD «съезжал» (баг, найден пользователем).** Две причины. 1) В панель сначала вкладывали `NSHostingView` с `autoresizingMask`, а потом меняли размер панели — autoresizing прибавлял разницу ещё раз, содержимое становилось шире панели (880 при 440) и уезжало вправо. **Правило: сначала `setFrame` окна, потом `hosting.frame = contentView.bounds`.** 2) `NSHostingView.fittingSize` меряет текст без переноса, а `.frame(maxWidth:)` растягивает вью до предложенной ширины. Размер — `NSHostingController.sizeThatFits(in: maxSize)` без `maxWidth`-рамки. Второстепенная строка (превью текста) — параметр `detail:`, а не `"\n"` в тексте. Покрыто `HUDLayoutTests`.
- **Пустое место сверху у панелей (найдено пользователем).** У `FloatingPanel` скрытый, но настоящий заголовок окна (`.titled` + `.fullSizeContentView`). `NSHostingView` считал его безопасной зоной и сдвигал содержимое на ~28 pt вниз, а вью ещё добавляли свои отступы. Решение: `hosting.safeAreaRegions = []` в `PanelService`. Отступ сверху задаёт само вью, как и остальные (обычно 16 pt).

### Распознавание и экран

- **OCR.** Снимок экранов — `context.areaSelection.selectArea()` (Core/Screen): ScreenCaptureKit делает снимки всех экранов **без окон самого FastUtils**, поверх показываются оверлеи с замороженной картинкой; результат — `AreaSelection` с уже вырезанным `CGImage`. Пересчёт точек в пиксели — `ScreenSnapshot.pixelRect` (по реальному отношению размеров картинки и экрана, Y переворачивается). Распознавание — Swift-API Vision `RecognizeTextRequest` (macOS 15+); координаты строк нормализованные, начало внизу слева. Языки храним коротко (`ru`, `en`) — так их отдаёт `supportedRecognitionLanguages.map(\.minimalIdentifier)`; на macOS 27 поддерживается 33 языка. Первое распознавание в процессе медленное (~25 с в тестах — загрузка модели), дальше быстро.
- **Разрешение на запись экрана.** Не проверяем его заранее через `CGPreflightScreenCaptureAccess` (может быть устаревшим), а просто пробуем снять экран. При ошибке `ScreenCaptureError.classify`: `SCStreamError.userDeclined` или отрицательный preflight → `.notPermitted` (запрос разрешения и HUD), остальное → `.failed` (HUD «не удалось сделать снимок», в Системные настройки не отправляем).
- **Оверлей.** Окна под курсором берутся из `CGWindowListCopyWindowInfo` (слой 0, не наши, крупнее 40 pt) **до** показа оверлеев; координаты Window Server — от верхнего края основного экрана (`flipToAppKit`). Лупа рисует увеличенный фрагмент замороженного снимка (`interpolationQuality = .none`).

### Буфер обмена, история, вставка

- **Разрешение на буфер обмена (macOS 15.4+).** `NSPasteboard.general.accessBehavior`: `.default` — приложение ещё не вызывало системный запрос и не видно в Системных настройках; первое программное чтение буфера показывает запрос и переводит в `.ask`; дальше пользователь может выбрать `.alwaysAllow`/`.alwaysDeny` в настройках. Чтение `changeCount` запрос **не** вызывает. Для процессов терминала агента значение уже `.alwaysAllow` — по нему нельзя судить о поведении FastUtils.
- **История буфера.** Поток данных: `PasteboardService` (Core) опрашивает `changeCount` раз в 0,5 с (таймер в режиме `.common`, `tolerance` 0,1 с; включается, только пока кто-то вызвал `startMonitoring()`), при изменении читает `PasteboardSnapshot` и публикует `ClipboardChanged`. Перед чтением данных Core смотрит только на типы и источник: пароли (concealed-типы, если модуль истории не разрешил `monitorReadsConcealed`) и приложения из `excludedApps` дают снимок с `contentsWithheld` **без чтения содержимого**. Настройки модуль истории передаёт в `PasteboardService` при запуске и при изменении (`applyMonitorSettings`: исключения, пароли, `monitorReadsImages`), при выключении сбрасывает. При выключенном «Хранить картинки» данные картинки не читаются вовсе (скриншот в TIFF — десятки МБ в главном потоке); `ImageHandler` поэтому узнаёт картинку и по типам, чтобы она пропускалась, а не сохранялась как её подпись. Источник — метка `org.nspasteboard.source`, которую ставят многие приложения, иначе активное приложение в момент обнаружения (опрос раз в 0,5 с: при быстром переключении возможна ошибка, это написано в настройках). Технические записи самого FastUtils — `writeText(_, recordInHistory: false)`: история их пропускает; результат OCR пишется с `true` и в историю попадает. Модуль: `ClipContentFactory` (обработчики типов, порядок важен), `HistoryStore` (actor: `history.sqlite` + `images/*.png` + `*_thumb.png`), дедупликация по SHA-256 содержимого — повтор поднимает запись наверх. Лимит текстовой записи — `ClipContent.maxTextBytes` (1 МБ, `limited(to:)`): сначала отбрасываются RTF/HTML, а если и сам текст больше — запись не сохраняется (хэш от этого не меняется: он считается только по тексту).
- **Хранилище: системная SQLite.** Решение по итогам прототипа: никаких GRDB, обёртка `Core/Storage/SQLiteDatabase` над `import SQLite3` (SQLite 3.54, FTS5 есть, но не нужен). Поиск — `LIKE` по колонке `search`, куда пишется текст, сведённый `folding([.caseInsensitive, .diacriticInsensitive])`: встроенный `LIKE`/`lower()` SQLite регистр понимает только для ASCII, а так «ПРИВЕТ» находит «привет» и «ежик» — «Ёжик». Спецсимволы `%`/`_`/`\` экранируются (`ESCAPE '\'`). `SQLITE_TRANSIENT` — C-макрос, в Swift объявлен вручную через `unsafeBitCast(-1, …)`. **Схема — через миграции:** `SQLiteDatabase.migrate(_:)` по `PRAGMA user_version`, список — `HistoryStore.migrations`. Новое изменение схемы — новый элемент в конце списка (`ALTER TABLE …`); уже выпущенные миграции не редактировать. Первая миграция — `CREATE … IF NOT EXISTS`, поэтому старые базы (версия 0) приняли её без изменений.
- **Вставка.** `context.paste.paste(snapshot, plainText:, into: targetApp, autoPaste:, restorePrevious:)`: пишет в буфер (с `recordInHistory: true` — история не дублирует, а поднимает запись; `restorePrevious` возвращает прежний буфер через `backup()`/`restore()`), при необходимости активирует приложение, ждёт ~60 мс и шлёт ⌘V через `KeystrokeSender` (`CGEvent`, key code `kVK_ANSI_V` — работает в любой раскладке). Без «Универсального доступа» возвращает `.copied(missingPermission: true)` — модуль показывает HUD «нажмите ⌘V». Приложение-цель запоминается **до** показа панели (`NSWorkspace.frontmostApplication`); наши панели не активируют FastUtils, поэтому цель обычно и так остаётся активной. В тестах — `FakeKeystrokeSender` через `AppContext.testing(keystrokes:)`, задержки обнулены.
- **Клавиатура в окне истории.** Стрелки, Enter, ⌘1…⌘9 и т.п. перехватывает локальный монитор `NSEvent` (только события окна панели), а остальное уходит в поле поиска; разбор клавиш — чистая функция `HistoryCommand.from(keyCode:modifiers:queryIsEmpty:)`. Пробел открывает предпросмотр только при пустом поиске, ⌫ без ⌘ редактирует поиск. Монитор снимается в `onClose` панели.
- **Список истории** грузится без RTF/HTML и с первыми 2 000 символов текста (`HistoryStore.listTextLimit`); для вставки и предпросмотра — полный `store.item(id)`. Грузится постранично (`HistoryViewModel.defaultPageSize` = 200): невидимая строка в конце списка (`canLoadMore`) подгружает следующую страницу при прокрутке или когда выделение дошло до конца. Новый поиск или фильтр начинает с первой страницы, а поиск идёт по всей базе, а не по загруженному. Раньше при каждом ⌥⌘V грузилось до `maxItems` (до 5 000) записей. Текстовый курсор для позиции окна — `TextCaret.rect()` через Accessibility (координаты AX — от верхнего края основного экрана, переворачиваются); многие приложения его не отдают → окно у курсора мыши. AX-вызовы синхронные и идут в главном потоке, поэтому стоит `AXUIElementSetMessagingTimeout` 0,25 с: со стандартными ~6 с зависшее приложение замораживало FastUtils.
- **Копирование выделения.** `context.paste.copySelection()`: ждёт отпускания ⌥/⌘ (иначе приложение получит ⌥⌘C), приостанавливает монитор буфера (`suspendMonitoring/resumeMonitoring` — при возобновлении всё изменённое за это время пропускается), шлёт ⌘C, ждёт смены `changeCount` до 300 мс и возвращает прежний буфер при **любой** смене (даже если пришла картинка, а не текст). Прежний буфер — `PasteboardService.backup()`: все элементы со всеми типами, включая чужие форматы (Figma, Office, несколько файлов); `PasteboardSnapshot` для этого не годится — он хранит только то, что нужно истории, и восстановление через него портило буфер. В тестах `FakeKeystrokeSender.onSend` изображает приложение, кладущее выделение в буфер.
- **Наведение после предпросмотра (баг, найден пользователем).** Предпросмотр (пробел) — `.overlay` поверх окна. После его закрытия SwiftUI `onHover` строк под ним переставал срабатывать до прокрутки (выделение «застывало»). Решение: `HistoryViewModel.onPreviewClosed` → на следующем витке `HoverTracking.refresh` сдвигает `NSScrollView` на 1 pt и обратно — AppKit пересобирает tracking areas, позиция не меняется. Пересоздавать список не годится: он прыгает с прежней позиции (пробовали, пользователю мешало).
- **Холодное окно истории.** Первое открытие после запуска занимало 190–300 мс (холодные SwiftUI, SQLite, миниатюры), дальше ~60 мс. Через 3 с после старта модуль один раз рисует `HistoryView` в невидимом `NSHostingView` (`prewarmHistoryWindow`, ~170 мс), и первое ⌥⌘V уже тёплое.

### Перевод

- **Apple Translation через SwiftUI-мост.** На macOS 15 `TranslationSession` можно получить только в `.translationTask`, поэтому `AppleTranslationEngine` — мост: запрос меняет `configuration` (если языки те же — `configuration.invalidate()`, иначе задача не перезапустится), невидимый `AppleTranslationHost` внутри окна перевода выполняет задачу и возвращает результат через continuation. **Окно должно содержать `engine.hostView`**, иначе перевод зависнет. Замыкание `.translationTask` объявлено `@Sendable`, а сессия не покидает его — иначе Swift 6 ругается «sending 'session' risks causing data races» (по умолчанию замыкание считается принадлежащим главному потоку). `TranslationError.notInstalled` есть только с macOS 26 — проверка под `#available`. Сопоставление ошибок — `case TranslationError.x:` в `switch error` (у `TranslationError` есть `~=`).
- **Окно перевода закрывалось мгновенно (баг, найден пользователем).** Если языковой пакет не скачан, Apple Translation пишет в лог «Text session reported that it needs user action; will present UI» и показывает своё окно загрузки. Оно забирало фокус, а `FloatingPanel` закрывается при потере фокуса — вместе с панелью пропадал и запрос. Исправление: `PanelHandle.holdsOpen` (панель не закрывается от потери фокуса, пока идёт перевод; после — снова берёт фокус), а `resignKey` решает о закрытии на следующем витке и не закрывает панель, если фокус ушёл в её лист или дочернее окно. **Правило: всё, что может показать системный UI поверх панели, должно держать `holdsOpen`.** Диагностика таких случаев — `log show --predicate 'process == "FastUtils"'` с поиском по `Translation`/`present`.
- **Язык и направление.** `LanguageDetector` (NaturalLanguage, порог уверенности 0,6; иначе `nil` и движок определяет сам), `TranslationDirection.target(detected:primary:fallback:)`; языки сравниваются по базовому коду (`ru` == `ru-RU`). Действия «только для других модулей» помечаются `FeatureAction(isInternal: true)` — их нет в меню, сочетаниях и онбординге (пример: `translate.show` для цепочки «распознать и перевести»).
- **Онлайн-перевод.** `DeepLEngine` (ключ с `:fx` → `api-free.deepl.com`, заголовок `Authorization: DeepL-Auth-Key …`; целевые EN/PT/ZH — `EN-US`/`PT-BR`/`ZH-HANS`; коды 403 → неверный ключ, 456 → лимит, 429 → частые запросы; `/v2/usage` для проверки ключа и остатка) и `GoogleEngine` (v2, ключ в заголовке `X-goog-api-key` — не в URL). Сеть — через протокол `HTTPClient` (в тестах `FakeHTTP`), таймаут 10 с. Длинный текст режется `TextChunker` по абзацам → предложениям → словам. Окно всегда получает `ResilientEngine`: кэш на 50 переводов (в памяти модуля) → выбранный движок → при `OnlineTranslationError` фоллбэк на Apple с причиной в окне. Результат фоллбэка в кэш **не** кладётся, иначе после появления сети тот же текст показывал бы перевод Apple с пометкой «DeepL недоступен». Ключи — только в Keychain (`translate.<engine>.apiKey` через `context.secrets`). `KeychainSecretStore` обновляет запись через `SecItemUpdate` (удалить и добавить заново — значит потерять ключ, если добавление сорвётся); поле ключа сохраняется после паузы в наборе (`APIKeysModel.scheduleSave`, 0,6 с), а не на каждый символ. Модель ключей одна на модуль (`lazy var keys`): `settingsView` пересобирается часто. Google сообщает об исчерпанной квоте и кодом 403, поэтому причина берётся из тела ответа (`GoogleEngine.error(status:body:)`), иначе квота выглядела бы как «неверный ключ». В тестах интерфейсные строки не подключены: `String(localized:)` возвращает ключ — не сравнивай с переведённым текстом.
- **Google Cloud пользователя.** Проект `fast-utils`, API-ключ «FastUtils» ограничен только Cloud Translation API. Чтобы гарантированно не платить, квота «v2 and v3 general model characters per day» снижена до 16 000 (бесплатно — 500 000 символов в месяц, дальше $20 за миллион). При исчерпании квоты Google отвечает 429 → `OnlineTranslationError.quotaExceeded` → фоллбэк на Apple. Сам ключ нигде в проекте и заметках не хранится — только в Keychain пользователя.

### Раскладка и регистр

- **Замена текста — `context.paste.replaceSelectionOrLastWord(transform)`** (Core). Сначала спрашивает AX, есть ли выделение (`TextCaret.hasSelection()`, длина `kAXSelectedTextRange`; в тестах — `selectionProbe`). Выделение → ⌘C. Нет выделения → «последнее слово»: ⌘⇧← (до начала строки), ⌘C, → (схлопнуть выделение к курсору), ⇧← × длина слова и пробелов после него (по `Character`), ⌘V. Слово — последний кусок без пробелов (`LastWord.split`), поэтому знаки вроде `;` в «kj;rf» входят в слово. Буфер пользователя возвращается через `backup()`/`restore()`, монитор приостановлен, запись `recordInHistory: false`. Стрелки шлются с флагами `.maskSecondaryFn | .maskNumericPad`, как от настоящей клавиатуры.
- **Почему AX-проба.** VS Code и JetBrains по ⌘C без выделения копируют всю строку с `\n` — без пробы строка вставлялась бы второй раз. Если в скопированном есть перевод строки, замена отменяется. Если AX молчит (`nil`), сначала пробуем ⌘C как выделение — в таких приложениях без выделения возможен сбой, поэтому в настройках подсказка «выделите слово».
- **Таблица раскладок** — статическая ABC ↔ «Русская – ПК» (`RussianWin`, раскладки владельца) по физическим клавишам (`KeyboardLayoutMap`), не `UCKeyTranslate`: TIS из двух потоков роняет процесс. Если у пользователя появится другая русская раскладка (Apple «Русская»), таблицу надо дополнить. Переключение раскладки системы — `InputSourceSwitcher` (`TISSelectInputSource`, только главный поток), по первому языку раскладки (`ru`/`en`).

### Пипетка

- **Устройство.** `context.colorPicker.pickColor(label:)` (Core, `Core/Screen/ColorPickerService.swift`) — тот же снимок экранов без окон FastUtils, что у OCR, и по оверлею на экран. Общие части с выделением области — в `Core/Screen/ScreenOverlay.swift`: `OverlayWindow`, лупа `Magnifier` (скруглённый квадрат; стили `.selection` с перекрестием для OCR и `.pixelGrid` с рамкой центрального пикселя для пипетки), `RGBColor`, `PixelPoint`, `ScreenSnapshot.pixel(at:)`/`point(ofPixel:)`/`color(atPixel:)`/`pixels(around:count:)`. Модуль `FeatureColor` — только форматы (`ColorFormat`), настройка `color.format` и HUD.
- **Пиксели, а не точки.** Позиция лупы хранится в пикселях снимка (начало сверху слева), стрелки двигают на один физический пиксель (на Retina — 0,5 pt). Реальный курсор переносится следом `CGWarpMouseCursorPosition` (координаты от верхнего края основного экрана), иначе следующее движение мыши отбросит лупу назад.
- **sRGB.** Снимок ScreenCaptureKit — в пространстве экрана (Display P3). Пиксель рисуется в 1×1 sRGB-контекст, CoreGraphics переводит цвет — так HEX совпадает с CSS (±1). Покрыто тестом на P3-картинке.
- **Лупа рядом с курсором** (решение пользователя: лупа на курсоре его перекрывала). Курсор — перекрестие, квадратная лупа справа снизу, у краёв экрана переносится влево/вверх, место под подпись учтено (`PickerLayout.loupeFrame`, покрыто тестами). Если понадобится скрыть курсор: `NSCursor.hide()` у фонового (`LSUIElement`) приложения не работает — ставь прозрачный курсор 1×1 на каждом `cursorUpdate`/`mouseMoved`.
- **Без затемнения.** Оверлей пипетки не затемняет экран, иначе на лупе были бы искажённые цвета. Время открытия — в логе (`Color picker opened in N мс`, категория `colorPicker`), цель < 200 мс. Цвет в лог не пишется: это содержимое буфера.
- **HUD с образцом** — `context.hud.show(_, detail:, swatch: RGBColor)`: кружок цвета вместо значка.

### Скриншот с рисованием

- **Устройство.** Модуль `FeatureScreenshot`: снимок — общий `context.screenCapture` (тот же, что у OCR и пипетки), оверлеи — `OverlayWindow` из Core. `EditorSession` ведёт этапы «выделение → рисование» и плавающую панель; `EditorView` — оверлей одного экрана (выделение повторяет OCR: рамка, клик по окну, лупа); `EditorDocument` — область, рисунки, назад/вперёд (снимки массива рисунков; новое действие очищает «вперёд»); `EditorGeometry` — чистая геометрия (ручки, ⇧, наконечник стрелки, место панели), покрыта тестами.
- **Координаты.** Рисунки и область хранятся в точках экрана редактирования (начало снизу слева). `ScreenshotExporter.render` вырезает `pixelRect` области из снимка и рисует поверх в контексте размером в пикселях (`scaleBy` пиксели/точки) — линии и текст в полном разрешении Retina. Рисует тот же `AnnotationRenderer`, что и экран; для текста нужен `NSGraphicsContext.current` вокруг CGContext.
- **Панель** — `NSPanel` уровня `.screenSaver + 1` (выше оверлеев), никогда не становится key (`canBecomeKey = false`): клавиатура остаётся у оверлея (Esc, ⌘Z, надписи). Чтобы кнопки срабатывали с первого клика в не-key окне — `NSHostingView` с `acceptsFirstMouse = true`. Перетаскивание — за ручку слева по `NSEvent.mouseLocation` (координаты SwiftUI-жеста двигаются вместе с окном и дают дрожание). Системную палитру `NSColorPanel` не используем — она открылась бы под оверлеем.
- **Клавиши** ⌘Z/⇧⌘Z/⌘C/⌘S ловит `EditorView.performKeyEquivalent` по key code (любая раскладка) — окно получает их раньше главного меню. Пока вводится надпись, они уходят полю ввода.
- **Надпись** — `NSTextField` без рамки на месте клика; Enter или клик мимо превращают её в рисунок (`origin` = рамка поля + 2 pt отступа текста), Esc отменяет. Готовые фигуры не двигаются и не редактируются — исправляется через «назад». Ластика нет (решение пользователя).
- **Правка надписей** (только инструменты «Надпись» и «Двигать» — `Tool.grabsText`, чтобы кисть рисовала поверх текста): клик выделяет (`EditorDocument.selectedText`, пунктир + ручка в правом нижнем углу рамки +4 pt), перетаскивание двигает, ручка плавно меняет шрифт (`EditorGeometry.scaledText`, верх на месте, 8…200 pt — у надписи свой `fontSize` в `.text(origin:string:fontSize:)`), двойной клик правит в поле ввода (`editingIndex`), ⌫/⌦ удаляют, Esc снимает выделение. Цвет и S/M/L на панели при выделенной надписи меняют её (`setColor`/`setSize`). Пока тянешь, рисуется копия (`displayedAnnotations`), в документ — один `replace` на `mouseUp`: один шаг отмены на жест. Выделение сбрасывается, если отмена убрала надпись или выбран рисующий инструмент.
- **Сохранение** — PNG в `screenshot.folder` (по умолчанию Рабочий стол), имя как у системы (`screenshot.fileName`), при совпадении « (2)». Копирование — `PasteboardService.write(PasteboardSnapshot(image:))`, картинка попадает в историю, если она хранит картинки. Последние инструмент, цвет и толщина запоминаются (`screenshot.tool/color/size`).
- **Курсоры.** Оверлей (`EditorView.cursor(at:)`): перекрестие при выделении; на краях области (вся длина ±5 pt, углы с приоритетом — `EditorGeometry.edge`) системный `NSCursor.frameResize(position:directions:)` (macOS 15); внутри по инструменту — кисть кружком своего цвета и толщины (`NSImage`-курсор, кэш), фигуры — перекрестие, надпись — I-beam, «Двигать» — открытая/сжатая рука; вне области — стрелка, и рисовать там нельзя. Над панелью курсор всегда стрелка (`ToolbarHostingView`: tracking area `.activeAlways`, без неё оставалось перекрестие или кисть с оверлея). Курсоры по кнопкам пробовали: SwiftUI `onHover` в фоновом приложении не срабатывает, а выбор по рамкам кнопок (`onGeometryChange`) работал криво — пользователь выбрал статичную стрелку, не возвращай это без его просьбы.
- **Сочетания:** скриншот — ⇧⌘2, распознавание текста — ⇧⌘1 (поменяли местами по просьбе пользователя). В `com.apple.symbolichotkeys` ⇧⌘1 и ⇧⌘2 не заняты; системные ⇧⌘3/⇧⌘4/⇧⌘5 не трогаем.
