# План разработки FastUtils

Разработка идёт строго по этапам, по порядку. Требования описаны в [TZ.md](TZ.md), а в этом файле — порядок работы и что считается готовым.

**Как работать с этим файлом:**
- Берём первый незавершённый этап. Следующий начинаем, только когда выполнены все пункты «Готово, когда».
- Выполненные задачи отмечаем `[x]` сразу, в том же изменении, где они сделаны.
- У текущего этапа меняем статус: ⬜ не начат → 🟡 в работе → ✅ готов.
- Если по ходу работы выяснилось, что задачу нужно разбить, перенести или добавить новую, правим этот файл. Если меняется само требование, сначала согласовываем с пользователем, потом правим TZ.md.
- Подводные камни и неочевидные решения, найденные на этапе, записываем в [CLAUDE.md](CLAUDE.md).

## Этап 0. Окружение и каркас сборки ✅

**Цель:** пустое приложение собирается одной командой, подписывается постоянным сертификатом и запускается как агент без Dock-иконки.

- [x] `git init`, `.gitignore` (`.build/`, `build/`, `*.app`, `.DS_Store`, `.swiftpm/`)
- [x] Создать самоподписанный сертификат подписи кода `FastUtils Dev` в «Связке ключей» и описать процесс в CLAUDE.md. Создан 2026-11-05 скриптом `scripts/create-signing-cert.sh` с согласия пользователя
- [x] `Package.swift`: таргеты `FastUtilsApp` (executable), `Core`, `FeatureOCR`, `FeatureTranslate`, `FeatureClipboard` + тестовые таргеты. Платформа `.macOS(.v15)`, Swift 6 language mode
- [x] `Resources/Info.plist`: `LSUIElement = YES`, bundle id, версия, локализации ru/en. Описания разрешений для записи экрана и Универсального доступа macOS не использует — не добавляли
- [x] `Resources/FastUtils.entitlements` (без sandbox, hardened runtime)
- [x] `scripts/build.sh`:
  - `swift build -c release --arch arm64`
  - сборка `FastUtils.app` (Contents/MacOS, Contents/Resources, Info.plist, .icns, `.lproj`)
  - `codesign --force --options runtime --entitlements … --sign "FastUtils Dev"`
  - флаги `--install` (копировать в `/Applications`, перезапустить приложение) и `--debug` (debug-сборка)
- [x] Флаг `--run`: собрать и запустить с выводом логов (`log stream --predicate 'subsystem == "…"'`)
- [x] Временная иконка приложения (`.icns` через `iconutil`) и иконка меню (SF Symbol)
- [x] Минимальная точка входа: приложение запускается, в Dock ничего нет, в строке меню видна иконка с пунктом «Выйти»

**Готово, когда:** `scripts/build.sh --install` собирает и устанавливает приложение. После пересборки ранее выданное разрешение (например, запись экрана) **не сбрасывается**. `swift test` проходит.

> Итог: требование подписи (designated requirement = bundle id + хэш сертификата) совпадает у разных сборок — проверено. Сквозную проверку с реально выданным разрешением делаем на этапе 3, когда приложение начнёт запрашивать разрешения.

## Этап 1. Ядро и модульная система ⬜

**Цель:** ядро из TZ.md §12, в котором модули регистрируются одной строкой и автоматически получают меню, настройки и жизненный цикл.

- [ ] Протоколы `Feature`, `FeatureAction`, типы `FeatureID`, `ActionID`, `ActionInput`, `ActionOutput`, `MenuItemDescriptor`, `Permission`
- [ ] `AppContext`: контейнер сервисов, передаётся модулям через `init(context:)`. Без синглтонов
- [ ] `FeatureRegistry`: список модулей из `FeatureList.swift`, вызов `start()`/`stop()` при включении и выключении
- [ ] `ActionRegistry`: регистрация и вызов действий по `ActionID`, в том числе действий другого модуля
- [ ] `EventBus`: типизированные события через `AsyncStream`, несколько подписчиков
- [ ] `SettingsStore`: настройки с пространством имён модуля поверх `UserDefaults` + обёртка Keychain для секретов
- [ ] `StorageService`: каталог данных модуля в `~/Library/Application Support/FastUtils/<featureID>/`
- [ ] Логгер с категорией модуля (`os.Logger`, subsystem = bundle id)
- [ ] `MenuBarController`: меню строится из `menuItems` включённых модулей + общие пункты (Настройки…, О программе, Выйти)
- [ ] Окно настроек: вкладки «Основные», «Сочетания клавиш» (пока пустая), вкладки модулей из `settingsView`, «Разрешения» (пока пустая), «О программе»
- [ ] Три модуля-заглушки (OCR, Translate, Clipboard) с одним тестовым действием каждый, которое показывает alert или пишет в лог
- [ ] Юнит-тесты: регистрация модулей, вызов действий по id, включение/выключение, пространства имён настроек, EventBus

**Готово, когда:** заглушки видны в меню и настройках. Выключение модуля в настройках убирает его пункт меню и вызывает `stop()`. Новый модуль-заглушка добавляется одной строкой в `FeatureList.swift`, правки ядра не нужны.

- [ ] Вкладка «Сочетания клавиш»: рекордер для каждого действия, сгруппированный по модулям, + «Сбросить»
- [ ] Проверка конфликтов: дубликат внутри приложения (запрет), список известных системных и популярных сочетаний (предупреждение), сочетание не удалось зарегистрировать (сообщение)

**Готово, когда:** сочетания вызывают тестовые действия заглушек в любом приложении и в любой раскладке. Переназначение и снятие работают сразу, без перезапуска. Выключенная функция освобождает своё сочетание.

## Этап 3. Разрешения, онбординг, HUD, панели ⬜

**Цель:** общая UI-инфраструктура, которую используют все функции.

- [ ] `PermissionsService`: статусы «Запись экрана» (`CGPreflightScreenCaptureAccess`), «Универсальный доступ» (`AXIsProcessTrusted`), «Вставка из других приложений» (macOS 26+, сначала исследовать API). Обновление статуса при возврате в приложение, deeplink в нужный раздел Системных настроек
- [ ] Вкладка «Разрешения» в настройках: показываются разрешения, которые требуют включённые модули
- [ ] Окно онбординга при первом запуске (TZ.md §9): описание, сочетания, разрешения со статусами, «Запускать при входе», «Готово»
- [ ] Запуск при входе через `SMAppService.mainApp`
- [ ] `HUDService`: плашка с текстом и иконкой, исчезает через ~1,5 с, не перехватывает клики, появляется на экране с курсором, позиция настраивается
- [ ] `PanelService`: базовая плавающая `NSPanel` (non-activating, поверх всех окон, `canJoinAllSpaces` + `fullScreenAuxiliary`), позиционирование у курсора с учётом границ экрана, закрытие по Esc и клику мимо, режим «закреплено»
- [ ] Проверить панели поверх полноэкранного приложения и на втором мониторе

**Готово, когда:** онбординг показывается один раз и корректно отражает статусы. Тестовые HUD и панель из заглушек работают поверх полноэкранных приложений, на любом мониторе и не крадут фокус.

## Этап 4. OCR: распознавание текста с экрана ⬜

**Цель:** функция 1 полностью по TZ.md §5.1–5.5.

- [ ] `ScreenCaptureService`: снимок всех экранов через `SCScreenshotManager` в нативном разрешении (вынести в Core)
- [ ] Оверлей выделения (в Core, для повторного использования): окно на каждый экран с замороженным снимком, затемнение, перекрестие, рамка, размеры, Esc и правый клик для отмены, пробел для перемещения рамки
- [ ] Вырезание области с учётом `backingScaleFactor` и разных масштабов мониторов
- [ ] `TextRecognizer`: Vision `.accurate`, языки из настроек, языковая коррекция, апскейл мелких областей
- [ ] Цепочка `TextPostProcessor`: порядок строк, режим «как на экране» / «склеивать абзацы», удаление переносов с дефисом, чистка пробелов
- [ ] Результат пишется в буфер через `PasteboardService`, HUD «Скопировано: N символов» / «Текст не найден» (в последнем случае буфер не меняется)
- [ ] Обработка отсутствия разрешения на запись экрана
- [ ] Вкладка настроек OCR: языки, режим переносов, «показывать результат в окне», звук
- [ ] Действие `ocr.captureText` с выходом `.text`, чтобы этап 9 мог строить цепочки
- [ ] Тесты пост-обработки на фиксированных наборах строк. Тест распознавания на тестовых картинках (русский, английский, смешанный текст, две колонки)

**Готово, когда:** ⇧⌘2 → выделение → текст в буфере не дольше чем через 1 с. Всё работает на Retina и внешнем мониторе и поверх полноэкранных приложений. Esc ничего не меняет.

## Этап 5. История буфера: отслеживание и хранение ⬜

**Цель:** всё скопированное надёжно сохраняется, пароли и исключения отфильтрованы. Окна истории на этом этапе ещё нет.

- [ ] Решить, чем хранить историю: SwiftData или GRDB. Сделать прототип поиска на 5 000 записей и записать решение в CLAUDE.md
- [ ] `PasteboardService` (Core): единая точка чтения и записи буфера, флаг «запись сделана самим приложением»
- [ ] `PasteboardMonitor`: таймер 0,5 с (tolerance ~0,1 с), сравнение `changeCount`, чтение содержимого только при изменении, публикация `clipboardChanged` в `EventBus`
- [ ] Модель `ClipItem` и протокол `ClipContentHandler`. Обработчики: текст (+RTF/HTML), изображение, файлы, URL
- [ ] Фильтры: concealed/transient/auto-generated типы, менеджеры паролей, список приложений-исключений (по frontmost-приложению), пустые строки, пауза
- [ ] `HistoryStore`: запись в БД, изображения в файлы, генерация превью ~200 px, дедупликация по хэшу (поднять наверх), закрепление
- [ ] Ограничения: число записей, срок хранения, размер изображения. Закреплённые записи не удаляются
- [ ] Пауза записи из меню (5 мин / 1 час / до перезапуска / пока не включу) + состояние иконки меню
- [ ] Вкладка настроек истории: лимиты, типы, исключения, «Очистить историю», занимаемое место
- [ ] Исследовать поведение приватности буфера на macOS 27, учесть в онбординге
- [ ] Тесты: фильтры, дедупликация, лимиты, сохранение между перезапусками

**Готово, когда:** текст, картинки и файлы, скопированные любым способом, попадают в историю. Пароль из Связки ключей не попадает. История переживает перезапуск. В простое приложение не нагружает CPU.
